All components below are registered in `components/docs/mdx.tsx`. Use them directly in an MDX page. Prefer the simplest component that helps the reader complete the task.

## Tabs and code blocks

Tabs keep alternatives together. Our request examples share `groupId="docs-request-language"` with `persist`, so the selected language follows the reader between guides. Use explicit `value` props on every tab.

<Tabs items={["curl", "TypeScript"]} groupId="docs-request-language" persist>
<Tab value="curl">

```bash title="Terminal"
curl https://your-app.example/api/v1/workspace \
  -H "Authorization: Bearer $WORKSPACE_API_KEY"
```

</Tab>
<Tab value="TypeScript">

```ts title="Server-side request"
const response = await fetch("https://your-app.example/api/v1/workspace", {
  headers: { Authorization: `Bearer ${process.env.WORKSPACE_API_KEY}` },
});
```

</Tab>
</Tabs>

````mdx title="Tabs with labeled code"
<Tabs items={["curl", "TypeScript"]} groupId="docs-request-language" persist>
  <Tab value="curl">

```bash title="Terminal"
curl https://your-app.example/api/v1/workspace
```

  </Tab>
  <Tab value="TypeScript">Your TypeScript example goes here.</Tab>
</Tabs>
````

The abbreviated source example above demonstrates formatting. Real workspace requests also require the Authorization header shown in the live example.

## Accordions for troubleshooting

<Accordions type="multiple">
  <Accordion title="Why is the rename tool missing?">
    Read-only connections advertise only read tools. Reconnect with
    read-and-rename access to enable renaming.
  </Accordion>
  <Accordion title="Can I use this pattern in my own guides?">
    Yes. Group related optional details under clear symptom or question labels.
    Keep essential instructions visible in the page.
  </Accordion>
</Accordions>

```mdx title="Accordion"
<Accordions type="multiple">
  <Accordion title="Why is the rename tool missing?">
    Explain the cause and how to resolve it.
  </Accordion>
</Accordions>
```

`Endpoint` is the template's small presentational component. `TypeTable` is provided by Fumadocs. Keep the descriptions consistent with the [generated OpenAPI document](/api/openapi).

## More Fumadocs resources

The [official component library](https://www.fumadocs.dev/docs/ui/components) includes additional options such as zoomable images, inline tables of contents, and dynamic code blocks. Add them when your content needs them, register them in the shared MDX file, and verify their Markdown output and mobile behavior.
