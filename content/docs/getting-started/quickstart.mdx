---
title: Make your first request
description: Create a workspace key and retrieve your workspace ID in three steps.
---

You need a running installation and an **Owner** or **Admin** workspace role. If you are setting up the template for the first time, start with [buyer setup](/docs/getting-started/setup).

<Steps>
<Step>

## Create an API key

Open **Integrations → API keys** in your application. Create a named **Read only** key, choose its expiry, and copy it when it is revealed.

Save the key as `WORKSPACE_API_KEY` in the environment of the terminal or server running your script. Replace `https://your-app.example` below with your application origin. The curl examples use a POSIX shell; select TypeScript for a Node.js example.

<Callout title="Keep the key on the server">
  The secret is shown once. Store it privately; never put it in browser code, a
  public environment variable, or a URL.
</Callout>

</Step>
<Step>

## Get your workspace

<Tabs items={["curl", "TypeScript"]} groupId="docs-request-language" persist>
<Tab value="curl">

```bash title="Terminal"
curl https://your-app.example/api/v1/workspace \
  -H "Authorization: Bearer $WORKSPACE_API_KEY"
```

</Tab>
<Tab value="TypeScript">

```ts title="get-workspace.ts"
const key = process.env.WORKSPACE_API_KEY;
if (!key) throw new Error("Set WORKSPACE_API_KEY first");

const response = await fetch(
  "https://your-app.example/api/v1/workspace",
  { headers: { Authorization: `Bearer ${key}` } },
);
const result = await response.json();
if (!response.ok) throw new Error(result.error);
console.log(result.data);
```

</Tab>
</Tabs>

</Step>
<Step>

## Use the workspace ID

A successful request returns the workspace authorized by this key:

```json title="200 OK"
{
  "data": {
    "id": "4fd7c62d-66c5-41d3-bc28-6b5ec0c17322",
    "name": "Acme Studio",
    "slug": "WRK7M2Q9A4X1B",
    "created_at": "2026-01-15T10:30:00+00:00"
  }
}
```

`id` is the workspace UUID. `slug` is the permanent readable identifier shown in the application. The key is already bound to this workspace, so the read and rename endpoints do not need a workspace ID parameter.

</Step>
